# Noir 1.0 alpha and clean `main` handoff

This is the repository-owned handoff for the `1.0.0-alpha.1` candidate. Live
evidence and residual risk belong in [release readiness](release-readiness.md).

## Fixed boundaries

- `leoafarias/noir` remains private during this handoff.
- Noir consumes canonical OpenTUI v0.5.1 at commit
  `ad9a818d7a9d73f3386e92a445d0feb4b395c69e` and ships its six official
  release libraries unchanged.
- Automatic push/pull-request CI is ordinary. Manual workflow dispatch or
  rerun, native builds, tags, releases, publication, and visibility changes
  remain separately controlled.
- No compatibility shim is retained for removed fork-only prerelease APIs.
- Never force-push `main`.

## Candidate verification

1. Run focused ABI, paint, health, path, line-ending, workflow, and asset tests.
2. Run formatting, fatal-info analysis, architecture tests, and the complete
   ordinary suite.
3. Verify the six local assets, official archives, selected exports, generated
   bindings, notices, documentation links, and publish dry-run.
4. Verify an isolated downstream consumer can resolve all three API tiers,
   analyze, run the health check, and capture a rendered frame.
5. Obtain independent behavior and full-diff review and resolve every concrete
   finding.

## Private history cutover

1. Push the implementation branch normally and require a fresh staged CI run;
   Ubuntu must pass before desktop jobs begin.
2. Create `git bundle --all`, verify it, and mirror it outside the repository.
3. Reuse the reviewed final tree with `git commit-tree` to create one
   parentless commit named `feat: prepare Noir 1.0.0-alpha.1`.
4. Push that commit as new `main` without renaming the current local branch,
   set private `main` as default, and retain read-only/immutable-action policy.
5. Require clean-`main` staged CI to pass. Clone the private default branch
   afresh, verify the exact reviewed tree, and rerun the local gates.
6. Only after the clean clone succeeds, close PR #1 and delete remote `master`
   and `leoafarias/havana-v1` tips.

## Recovery and release boundary

The verified external bundle preserves private preparation history. A later
public launch must use a fresh repository populated from verified clean
`main`; do not make this preparation repository public in place.

This handoff does not create a tag, GitHub release, pub.dev publication, native
build, or visibility change.
