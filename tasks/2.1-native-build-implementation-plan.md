# Phase 2 native-build wrapper implementation plan

This plan implements the approved
[Phase 2 native-build contract](2.0-native-build-contract.md). The contract and
[1.0 release plan](1.0-release-plan.md) remain authoritative. The wrapper only
produces and verifies candidate libraries; tracked native artifacts, the native
manifest, ABI surfaces, generated bindings, the OpenTUI gitlink, and recovery
URLs remain read-only.

## Observable behavior

- `dart run scripts/build_opentui_candidates.dart --plan` validates the
  repository, source pin, Docker availability, ignored work area, recipe, and
  run-directory safety, then prints the exact two-root six-target plan without
  creating build outputs.
- `dart run scripts/build_opentui_candidates.dart --execute-native-build`
  performs the authorized build only from a clean committed recipe. No shorter
  execution alias and no install, manifest-update, upload, tag, release, or
  publication mode exists.
- The runner recipe uses the pinned Linux arm64 Debian base, the
  `2026-08-01T00:00:00Z` Debian snapshot, Zig 0.14.1 with both official checksum
  and minisign verification, and the pinned `zg` package hash. This timestamp
  is part of the reviewed recipe and must not be selected dynamically.
- Root A builds the approved target matrix in contract order and root B builds
  it in reverse order. Both roots use distinct read-only source mounts,
  outputs, local caches, and global caches. Every target is a separate
  networkless, non-TTY container invocation.
- Verification rejects missing or extra executable outputs, wrong formats or
  machines, incomplete exports, a non-15.0 macOS floor, disallowed embedded
  paths, or nonidentical normalized root pairs.
- Windows verification requires the pinned `opentui.dll`/`opentui.pdb` install
  pair, selects only the DLL, and records it under Noir's `libopentui.dll`
  candidate/package name. It inspects the DLL's PE export directory with
  `llvm-readobj --coff-exports` instead of relying on a COFF symbol table.
- Normalization uses the runner-pinned `llvm-strip --discard-all`; a focused
  driver regression pins the exact command that removes Mach-O `N_SO` and
  `N_OSO` build/cache paths without removing defined external exports.
- A fail-closed format parser canonicalizes only Mach-O `LC_UUID` and PE
  timestamp/debug-build metadata before the discard step. Focused tests pin
  the exact fields, preserve all other bytes, and reject structural drift.
- Successful execution records build information, an unsigned local SLSA v1
  statement, logs, inspections, hashes, protected-path proofs, and a sorted
  evidence inventory. It mirrors candidates and recovery material outside all
  Conductor workspaces, verifies the mirror byte-for-byte, and only then writes
  the matched-candidate success marker.
- Cleanup and destination guards accept only exact marker-owned directories
  under `.context/` and categorically reject tracked native destinations.
- CI adds one read-only `native-wrapper` job with a ten-minute job timeout and
  five-minute focused steps. It runs only the normalization regression and
  guarded `--plan`; it cannot execute a native build, publish, release, or
  upload artifacts.

## Implementation and RED tests

The tracked implementation surfaces are
`scripts/build_opentui_candidates.dart`, focused libraries under
`scripts/native_build/`, the immutable recipe under
`scripts/native_build/recipe/`, and tests under `test/scripts/native_build/`.
External process and inspection seams are injected so unit tests do not invoke
Docker, Zig, LLVM, or Git.

Before implementation, focused tests will establish RED failures for:

1. the exact matrix, macOS target suffixes, and root-B-only reversal;
2. explicit execution-mode parsing plus repository, pin, and cleanliness
   guards, including temporary Git fixtures where process behavior matters;
3. networkless/non-TTY container argv, read-only sources, isolated paths and
   caches, fixed environment, hardening, and bounded temporary storage;
4. the exact `llvm-strip --discard-all` normalization command plus artifact
   rejection for missing/extra files, path leaks, wrong
   format/machine/exports/floor, and unequal normalized pairs;
5. the bounded, read-only CI validation job;
6. marker-owned cleanup and tracked-destination refusals; and
7. deterministic build information, provenance, evidence inventory, and mirror
   verification from injected inputs.

## Ordered execution and gates

1. Commit this implementation plan as the docs-only slice.
2. Add the focused tests and confirm they fail for missing behavior.
3. Implement the minimum coherent wrapper and recipe until focused tests pass.
4. Run format, strict analysis, architecture tests, the ordinary suite without
   `restricted-process-lifecycle`, tracked manifest verification, and
   `git diff --check`.
5. Commit and push the verified wrapper, enable repository Actions only after
   the local gates pass, and verify the bounded job through a same-repository
   pull request. Enabling Actions does not authorize a release or publication
   workflow dispatch.
6. After local and GitHub validation, inspect `--plan`, run the explicitly
   authorized native build, preserve and mirror the evidence, report both
   six-target SHA-256 tables, and stop for separate candidate-replacement
   approval.

Any contract stop condition retains failure evidence when possible and ends
the run without modifying or selecting tracked native artifacts.
