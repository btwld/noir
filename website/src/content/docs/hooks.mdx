# Hooks

Hooks let a widget keep local state and manage resources without a separate
`State` class. Extend `SignalWidget`, or use `SignalBuilder` for an inline
subtree. Both hosts support lifecycle hooks and signal hooks. Use `useState`
for a counter, `useTextEditingController` for an editable field, or `useEffect`
to start and clean up a timer.

<PrereleaseNotice>
  Hooks are part of the optional `noir_signals` package. It requires the
  unreleased Noir alpha.5, so these examples currently need a repository
  checkout and access to the private Noir repository.
</PrereleaseNotice>

## Start with a runnable example

With Dart 3.10 or later, run these commands from the Noir repository root:

```sh
dart pub get
dart run packages/noir_signals/example/counter.dart
```

The [counter source](https://github.com/conceptadev/noir/blob/main/packages/noir_signals/example/counter.dart)
uses `SignalWidget` and `useState`. Press Enter or Space, or click the button,
to increment the count. Ctrl+C exits.

For a larger app, follow [Build a task list](/docs/signals-task-list). You’ll
add an editable field, task state, a computed count, and a visibility filter,
with code and a screenshot at each step. The
[example directory](https://github.com/conceptadev/noir/tree/main/packages/noir_signals/example)
contains all three runnable apps.

## Import hooks alongside Noir

The checkout resolves both packages together. In a file that uses hooks, import:

```dart
import 'package:noir/noir.dart';
import 'package:noir_signals/noir_signals.dart';
```

Files that only use Noir widgets need just `package:noir/noir.dart`.
To use the companion in your own project before publication, follow the
[local dependency setup](/api#evaluate-repository-source).

After both packages are published, the hosted dependency versions will be:

```yaml
dependencies:
  noir: ^0.0.1-alpha.5
  noir_signals: ^0.0.1-alpha.0
```

Use the local setup above until then.

## Tie cleanup to the resource

This widget owns an observed count and a periodic timer. The effect starts the
timer, and the returned callback cancels it when the interval changes or the
widget leaves the tree:

```dart
import 'dart:async';

import 'package:noir/noir.dart';
import 'package:noir_signals/noir_signals.dart';

class PollingBadge extends SignalWidget {
  const PollingBadge({required this.interval, super.key});

  final Duration interval;

  @override
  Widget build(BuildContext context) {
    final ticks = useState<int>(0);

    useEffect(() {
      final timer = Timer.periodic(interval, (_) {
        ticks.value++;
      });
      return timer.cancel;
    }, <Object?>[interval]);

    return Row(
      spacing: 1,
      children: [
        const Badge(label: 'POLLING', variant: BadgeVariant.info),
        Text('${ticks.value} checks'),
      ],
    );
  }
}
```

`useState` owns and observes a `ValueNotifier`. Changing `ticks.value` requests
a rebuild. The timer callback runs later, after the effect has returned, so it can
update the state.

Effects run synchronously during build. Use them to start external work and
return its cleanup. Handle button presses in `onPressed`. An effect or cleanup
must not synchronously update an observed hook value.

## Preserve hook order

Stateful hooks use call order as identity. Call them unconditionally at the top
level of `build`, in the same order on every build. Do not call a hook from a
branch, loop, event callback, effect, or cleanup function.

Keys control when a hook replaces its retained resource. When the keys for `useEffect` change,
Noir installs the new effect and releases the previous resource. Without keys,
the cleanup and effect run on every build. An empty key list keeps the resource
for the life of that mounted hook slot.

Top-level custom hooks should begin with `use`. Keep owned notifiers private
when callers need only a value and callback:

```dart
typedef CounterState = ({int value, VoidCallback increment});

CounterState useCounter([int initialValue = 0]) {
  final counter = useState(initialValue);
  return (value: counter.value, increment: () => counter.value++);
}
```

## Match the hook to the job

| Need                                        | Start with                                                           |
| ------------------------------------------- | -------------------------------------------------------------------- |
| Observed local value                        | `useState`                                                           |
| Retained object, Future, or Stream identity | `useMemoized`                                                        |
| Acquire and release an external resource    | `useEffect`                                                          |
| Read a Listenable and rebuild               | `useListenable` or `useValueListenable`                              |
| Editable text, focus, or scrolling          | `useTextEditingController`, `useFocusNode`, or `useScrollController` |
| Time-based values                           | `useAnimationController` and `useAnimation`                          |
| Mutable bookkeeping that must not rebuild   | `useRef`                                                             |

Create a Future or Stream outside `build`, or retain it with `useMemoized`.
Creating it on every build restarts the asynchronous work.

## When a State class is clearer

Use a state class when several lifecycle methods, related resources, or a
longer transition are easier to understand together. Use a hook when one
concern can be named and composed without hiding who owns it. `SignalBuilder` is
available when a small stable subtree needs hooks inside an ordinary
`StatefulWidget`.

Hot reload forwards `reassemble` to retained hook state. An ordinary build
reports reordered or conditional stateful hooks instead of silently accepting
the new identity. Read [State and lifecycle](/docs/state-lifecycle) for the
underlying ownership model, [Signals](/docs/signals) for the reactive state
the same package adds, and run the repository’s
[counter example](https://github.com/conceptadev/noir/blob/main/packages/noir_signals/example/counter.dart)
for a complete input-driven app.
