# Widget catalog

Start with the job the interface must do. Every published name below links to
its generated signature. Match that reference to the version in your
`pubspec.lock`.

[`TextInput`](/docs/widgets/text-input) has a curated page with its properties,
key handling, and ownership rules.

## Layout and composition

| Need                                    | Start with                                                     | Important distinction                                    |
| --------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------- |
| Horizontal or vertical children         | [`Row`][row], [`Column`][column], [`Flex`][flex]               | `spacing` inserts whole cells between children           |
| One child owns leftover space           | [`Expanded`][expanded], [`Flexible`][flexible]                 | Expanded fills its share; Flexible may use less          |
| Padding, alignment, or exact extent     | [`Padding`][padding], [`Align`][align], [`SizedBox`][sizedbox] | Keep each relationship in the widget that owns it        |
| Minimum or maximum size                 | [`ConstrainedBox`][constrainedbox]                             | A constraint is a range, not a promised size             |
| Themed titled region                    | [`Panel`][panel]                                               | Shrink-wraps content; width and height set exact extents |
| Fill, border, and child composition     | [`Container`][container], [`DecoratedBox`][decoratedbox]       | Use Container for composition; DecoratedBox only paints  |
| Overlapping children                    | [`Stack`][stack], [`Positioned`][positioned]                   | Positions are integer cell offsets                       |
| Children that continue onto another run | [`Wrap`][wrap]                                                 | Use Row when wrapping would be surprising                |
| A child that must read its own space    | [`LayoutBuilder`][layoutbuilder]                               | Builds during layout from the offered `BoxConstraints`   |

`LayoutBuilder` reports the space a parent offers. It is available in Noir
0.0.1; see [Installation](/docs/installation).

Read [Layout in terminal cells](/docs/widgets-layout) before you fix widths
across a screen. Terminal proportions make one row of spacing visually larger
than one column.

## Text, status, and feedback

| Need                 | Widget                                                         | Notes                                                                    |
| -------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Plain or styled text | [`Text`][text], [`RichText`][richtext], [`TextSpan`][textspan] | Width follows terminal graphemes, not Dart string length                 |
| Large glyph heading  | [`AsciiFont`][asciifont]                                       | Uses Noir's own terminal-safe font families                              |
| Compact state label  | [`Badge`][badge]                                               | Variants provide semantic defaults through Theme                         |
| Completion fraction  | [`ProgressBar`][progressbar]                                   | Width is explicit and resolves to eighth-cell steps                      |
| Ongoing work         | [`Spinner`][spinner]                                           | Remove it when work ends; use `SpinnerFrames.line` for ASCII-only output |
| Section rule         | [`Divider`][divider]                                           | Prefer one structural divider to borders around every child              |
| Shared visual values | [`Theme`][theme]                                               | Read values with `Theme.of(context)`                                     |

Use a ProgressBar for measurable work and a Spinner when progress is unknown:

```dart
Row(
  spacing: 1,
  children: [
    if (totalBytes == null)
      const Spinner(frames: SpinnerFrames.line)
    else
      ProgressBar(value: downloadedBytes / totalBytes, width: 24),
    Text(status),
  ],
)
```

## Input and selection

| Need                        | Widget                                         | Interaction model                                                       |
| --------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------- |
| Activate one command        | [`Button`][button]                             | Enter, Space, or primary pointer activation                             |
| Boolean value               | [`Checkbox`][checkbox], [`Switch`][switch]     | Use the label that best describes the resulting state                   |
| Value on a range            | [`Slider`][slider]                             | Arrow-key and pointer adjustment                                        |
| One-line editing            | [`TextInput`](/docs/widgets/text-input)        | Enter submits; default `maxLength` is 100                               |
| Attached suggestions        | [`Autocomplete<T>`][autocomplete]              | Caller controls options, status, selection, and async work              |
| Multi-line editing          | [`TextArea`][textarea]                         | Fixed by default; opt into wrapping, bounded growth, or Enter-to-submit |
| Vertical option list        | [`Select`][select]                             | Arrows or `j`/`k` change highlight; Enter confirms                      |
| Horizontal section switcher | [`TabSelect`][tabselect]                       | Fixed-width tabs by default; `tabWidth: null` sizes to labels           |
| Local raw key ownership     | [`Focus`][focus], [`FocusScope`][focusscope]   | Return `ignored` for keys the region does not own                       |
| Semantic key commands       | [`Shortcuts`][shortcuts], [`Actions`][actions] | Map keys to Intents, then Intents to application commands               |
| Pointer hit region          | [`PointerListener`][pointerlistener]           | Read `MouseEvent.localPosition` after hit testing                       |

`PointerListener.mouseCursor` selects a custom mouse shape. Interactive
controls provide hover pointers automatically. See
[Show a hand over an action](/docs/input-focus#show-a-hand-over-an-action) for
requirements and behavior.

`Select` and `TabSelect` share typed options but express different spatial
models:

```dart
Select<String>(
  options: const [
    SelectOption(name: 'Development', value: 'dev'),
    SelectOption(name: 'Production', value: 'prod'),
  ],
  height: 2,
  autofocus: true,
  onSelect: (_, option) {
    final environment = option.value;
    if (environment != null) applyEnvironment(environment);
  },
)
```

`Select.height` is visible rows and defaults to `8`. Set it to the option count
for a short list. [`SelectOption`][selectoption]`.value` is nullable.

`Autocomplete<T>` keeps request policy outside the widget. Supply an explicit
`AutocompleteStatus` and options from the application. Tab enters a ready list,
Enter or a primary click selects, and Escape dismisses the attached surface
while idle Escape stays available to an ancestor.

See [Handle input and focus](/docs/input-focus) for event order, controller
ownership, and focus traversal.

## Scrolling and data

| Need                  | Widget                   | Choose it when…                                                         |
| --------------------- | ------------------------ | ----------------------------------------------------------------------- |
| One oversized child   | [`ScrollBox`][scrollbox] | The content already exists as one widget subtree; tail follow is opt-in |
| Repeated visible rows | [`ListView`][listview]   | Rows should be built only for the visible window                        |
| Hierarchical rows     | [`TreeView`][treeview]   | Stable caller IDs need expansion and keyboard navigation                |
| Interactive dataset   | [`DataTable`][datatable] | Rows need aligned columns, selection, and caller-owned sorting          |
| Finite rich-text grid | [`TextTable`][texttable] | Cells need wrapping, borders, and row-major text selection              |

`DataTable` virtualizes its body and reports sort requests; your data owner
does the reordering. `TextTable` lays out a finite matrix of `InlineSpan` cells
and supports document-style selection. They solve different table problems.

[`TreeViewController`][treeviewcontroller] owns generic roots, expansion, and selection; path,
filesystem, or other domain behavior stays in the application. TreeView uses
Up and Down for visible selection, Right and Left for hierarchy navigation, and
one Enter or primary-click activation route.

## Overlays and menus

| Need                            | Widget                           | Boundary                                                      |
| ------------------------------- | -------------------------------- | ------------------------------------------------------------- |
| Custom transient content        | [`OverlayPortal`][overlayportal] | Caller owns placement, input, focus, and dismissal            |
| Centered blocking interaction   | [`Modal`][modal]                 | Closed focus loop and pointer barrier; caller supplies chrome |
| Commands anchored to a launcher | [`MenuAnchor`][menuanchor]       | Follows launcher geometry and owns outside-click dismissal    |

`Modal` keeps its ordinary child mounted, centers a fresh `modalBuilder`
subtree while open, loops Tab and Shift+Tab over live modal controls, restores
the captured focus node on close, and blocks every outside pointer event.
Escape dismisses by default; outside primary-button dismissal is opt-in.
Compose a `Panel` inside the builder, because Modal deliberately has no visual
style of its own.

```dart
final modal = ModalController();

Modal(
  controller: modal,
  initialFocusNode: cancelFocus,
  modalBuilder: (context) => Panel(
    title: 'Discard changes?',
    child: Row(
      spacing: 1,
      children: [
        Button(
          label: 'Cancel',
          focusNode: cancelFocus,
          onPressed: modal.close,
        ),
        Button(
          label: 'Discard',
          onPressed: () {
            discardChanges();
            modal.close();
          },
        ),
      ],
    ),
  ),
  child: Button(label: 'Open', onPressed: modal.open),
)
```

One [`ModalController`][modalcontroller] attaches to one live Modal. `open()` throws while
detached, `close()` is a detached no-op, and replacing the controller preserves
an open subtree without transition callbacks. Calling `open()` again promotes
that modal and reestablishes focus inside it. When a top modal closes, the
modal revealed below preserves a valid restored focus or repairs to an
available descendant.

Noir has one framework-owned root overlay. It does not expose public
`OverlayEntry`, nested overlays, transforms, linked layers, menu cascades, or
overlay animation APIs.

## Documents and media

| Need                        | Widget or type                                                   | Boundary                                                                        |
| --------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Selectable source           | [`CodeView`][codeview]                                           | Plain text by default; supply a `CodeHighlighter` for syntax ranges             |
| Unified or split patch      | [`DiffView`][diffview], [`UnifiedDiffParser`][unifieddiffparser] | Caller chooses view mode and owns any source action                             |
| GitHub-flavoured Markdown   | [`MarkdownView`][markdownview]                                   | Standalone mode scrolls; embedded mode delegates scrolling to a parent          |
| Terminal image              | [`Image`][image], [`TerminalImage`][terminalimage]               | File, network, encoded bytes, or RGBA; protocol support depends on the terminal |
| Semantic terminal link      | linked [`TextSpan`][textspan]                                    | The terminal decides whether and how the link is presented                      |
| Explicit selected-text copy | [`SelectedText`][selectedtext] and document callbacks            | OSC52 acceptance depends on terminal policy                                     |

For a read-only `DiffView` embedded in a decision surface, set
`canRequestFocus: false` so the enclosing modal keeps keyboard traversal.

A standalone Markdown document owns focus, selection, and its scrolling
viewport:

```dart
MarkdownView(
  markdown: releaseNotes,
  autofocus: true,
)
```

Check [Platform support](/docs/platform-limitations) before you depend on
terminal images, semantic links, or OSC52 clipboard behavior.

## State and motion

[`StatefulWidget`][statefulwidget] and its `State` are the normal retained state boundary.
[`ValueNotifier`][valuenotifier] and [`ChangeNotifier`][changenotifier] separate testable state from one widget.
[`AnimationController`][animationcontroller] with `TickerProviderStateMixin` or
`SingleTickerProviderStateMixin` drives time-based values. [`ThemeData`][themedata] carries
the shared visual values.

The optional companion package `noir_signals` offers the same ownership model
through composable hooks. Read
[State, identity, and ownership](/docs/state-lifecycle) to choose, and
[Manage state and resources](/docs/hooks) when one lifecycle concern should be
reusable.
