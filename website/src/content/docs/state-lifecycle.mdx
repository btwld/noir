# State and lifecycle

A `StatefulWidget` describes configuration. Its retained `State` object owns
local mutable values and resources. When a rebuild produces the same widget
type and key in the same place, Noir preserves that state.

## Update state from an event

Counter makes the sequence visible:

1. A focused key or left-pointer event calls a state method.
2. The method changes `_count` inside `setState`.
3. Noir rebuilds that widget subtree, then lays out and paints a new terminal
   frame.

```dart
void _incrementCounter() => setState(() => _count++);
```

The full example gives its pointer target a stable
`ValueKey<String>('increment')`, so headless tests can target the real control
without depending on terminal coordinates.

## Dispose what the state owns

Create a controller, focus node, subscription, or animation in the state that
owns it, then release it from `dispose`. Chat creates a
`TextEditingController`, transcript `ScrollController`, and `FocusNode` in
`initState`; Pulse owns an `AnimationController` and its listener. Both examples
dispose those resources explicitly.

`initState`, `didChangeDependencies`, `didUpdateWidget`, `deactivate`,
`dispose`, and `mounted` follow Noir’s documented lifecycle contract. Finalizers
are a safety net, not the primary owner.

## Choose a state class or a hook

`HookWidget` uses Noir’s normal retained widget lifecycle. Choose a state class
when it makes ownership easiest to see. Choose a hook when reusable lifecycle
behavior is the clearer unit. In either form, handle input in the event
callback—not in an effect.

```dart
final count = useState<int>(0);
Button(label: '+ Add one', onPressed: () => count.value++);
```

Read [Hooks](/docs/hooks) for call-order identity, cleanup, and controller
hooks. Then compare [Counter](/examples#counter) with the
[Hooks Counter source](https://github.com/leoafarias/noir/blob/main/example/hooks_counter.dart).
