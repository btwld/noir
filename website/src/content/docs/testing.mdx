# Testing

Noir has four supported test tools. Choose the smallest one that proves the
behavior you are changing.

| What you need               | Supported harness  |
| --------------------------- | ------------------ |
| Layout and widget behavior  | `WidgetTester`     |
| One rendered terminal frame | `BufferCapture`    |
| Parsed synthetic input      | `KeyDriver`        |
| Binding integration         | `createTuiTestApp` |

Use `BufferMatchers` for cell-level assertions. Visual goldens include style
and cursor sidecars unless they are deliberately text-only. Do not introduce a
fifth, example-specific harness.

## Test the behavior the user sees

Counter tests its visual hierarchy, keyboard and pointer activation, compact
dimensions, and mouse setup. Chat tests prompt submission, animated and stable
spinner states, transcript scrolling, focus traversal, and Escape behavior.
Motion tests assert timeline changes and cleanup instead of stopping after a
controller is constructed.

```sh
dart test test/example/counter_test.dart --concurrency=1
dart test test/example/hooks_counter_test.dart --concurrency=1
```

## Know what a headless recording proves

The six site recordings use `NoirDriver (NOIR_DRIVE=1)`. They exercise Noir’s
normal layout, paint, and parsed-input paths, but they do not prove raw-mode
input or escape rendering in a terminal emulator.

Each recording on [Examples](/examples) links to the focused Dart test that
proves its behavior.
