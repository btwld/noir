# Input and focus

Focus determines which widget receives keyboard input. Pointer events travel
through render-tree hit testing and arrive with `MouseEvent.localPosition`, so
widgets do not need to translate global terminal coordinates themselves.

## Give keyboard input one owner

Use `Focus` or `FocusScope` to decide who receives a `KeyEvent`. Interactive
controls such as Button, Checkbox, Switch, Select, and TextInput participate in
normal focus traversal. In
[Components](https://github.com/leoafarias/noir/blob/main/example/components_demo.dart),
Tab and Shift+Tab move focus, while Enter, Space, and a left click activate the
current control.

Focus-owning widgets use `FocusNodeOwnerStateMixin`. Give important controls a
stable `ValueKey<String>` when tests or headless driving need to identify an
intent without relying on coordinates.

## Edit text with a controller

Text editing uses `TextEditingController`. Chat owns one beside its prompt focus
node. Submitting trims the input, appends a user message, and starts an
asynchronous assistant turn. The app disposes the controller with its other
owned state.

```dart
late final TextEditingController _inputController;

void _submitPrompt() {
  final prompt = _inputController.text.trim();
  // Append the turn, then resolve the reply asynchronously.
}
```

## Make scrolling deliberate

`ScrollBox` wraps one overflowing child and can use a `ScrollController`. Chat
keeps its newest-first transcript navigable while preserving older history. Pub
Search gives its package detail pane independent focus and scrolling.

Add PageUp, PageDown, Home, End, and wheel behavior only where the component
documents it. See [Chat](/examples#chat) and
[Pub Search](/examples#pub-search) for complete flows.
