# Platform support and limitations

Noir is a prerelease, not a stable 1.0 release. It currently targets macOS,
Linux, and Windows on x64 and arm64. Android, iOS, and web are not supported.

<PrereleaseNotice>
  Release operations and the direct real-terminal parity matrix remain separate
  from ordinary headless verification.
</PrereleaseNotice>

## Check the macOS floor

The bundled macOS libraries require macOS 13.0 or later. Dart 3.10 native-asset
hooks declare a macOS 12 target, so a normal CLI build can succeed before the
native loader reports an incompatibility on macOS 12.

Run `dart run noir:health_check` to verify headless native-asset resolution. It
does not validate real terminal escape rendering.

## Account for known native boundaries

- Kitty, Sixel, and OSC52 acceptance depends on the terminal or multiplexer.
  The current candidate has not completed the separately authorized matrix for
  direct terminal checks.
- A source run beginning with a zero-width grapheme can diverge from the pinned
  native `bufferDrawText` paint path, even though Noir keeps source-correct
  layout semantics.
- A decorated box that straddles a clipped viewport edge can paint its border
  outside the native scissor rectangle.
- On an observed macOS/iTerm path, alternate-screen teardown can restore the
  launch cursor imperfectly. Apps must still dispose `TuiApp` so Noir releases
  owned resources and terminal modes.
- Hot reload rebuilds, lays out, and paints retained state. It does not rerun
  `main()` or `initState`, and some structural Dart changes require a restart.
