# Platform & Limitations

Noir is a prerelease candidate, not a stable 1.0 promise. Its currently
supported desktop targets are macOS, Linux, and Windows on x64 and arm64.
Android, iOS, and web are not supported targets.

<PrereleaseNotice>
  Current alpha release operations and a direct real-terminal parity matrix
  remain intentionally separate from ordinary headless verification.
</PrereleaseNotice>

## Platform floor

The bundled macOS libraries require macOS 13.0 or later. Dart 3.10’s native
asset hooks declare a macOS 12 target, so the normal CLI build can succeed and
the native loader can report the incompatibility later on macOS 12. Run

<code>dart run noir:health_check</code> to verify headless native-asset
resolution; it does not validate real terminal escape rendering.

## Known native boundaries

- Terminal protocol acceptance for Kitty, Sixel, and OSC52 depends on the
  terminal or multiplexer. The current candidate has not completed the
  separately authorized direct-terminal matrix.
- A run beginning with a source-level zero-width grapheme can diverge from the
  pinned native <code>bufferDrawText</code> paint path, even though Noir keeps
  source-correct layout semantics.
- A decorated box that straddles a clipped viewport edge can paint its border
  outside the native scissor rect.
- The observed macOS/iTerm alternate-screen lifecycle can restore the launch
  cursor imperfectly. Apps must still dispose <code>TuiApp</code> so owned
  resources and terminal modes are released.
- Hot reload rebuilds, lays out, and paints retained state; it does not rerun
  <code>main()</code> or <code>initState</code>, and some structural Dart
  changes require restart.
