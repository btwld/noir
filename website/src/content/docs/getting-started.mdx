# Getting started

You’ll build a counter, run it in a terminal, then change its label without
losing the count. You need Dart 3.10 or later on macOS, Linux, or Windows.

<PrereleaseNotice />

## Create the project

Create a Dart console application and move into it:

```sh
dart create -t console noir_demo
cd noir_demo
```

Add Noir from pub.dev:

<InstallCommand />

## Build the counter

Replace `bin/noir_demo.dart` with this complete app:

```dart
import 'package:noir/noir.dart';

void main() => runTuiApp(const CounterApp(), enableMouse: true);

class CounterApp extends StatefulWidget {
  const CounterApp({super.key});

  @override
  State<CounterApp> createState() => _CounterAppState();
}

class _CounterAppState extends State<CounterApp> {
  int _count = 0;

  void _increment() {
    setState(() {
      _count++;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Container(
      padding: const EdgeInsets.all(1),
      child: Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        spacing: 1,
        children: [
          Text('Count: $_count'),
          Button(
            autofocus: true,
            label: '+ Add one',
            onPressed: _increment,
          ),
        ],
      ),
    );
  }
}
```

`runTuiApp` mounts the widget tree and owns the terminal session. Mouse input is
opt-in; the `enableMouse` argument lets the Button receive a left click.

## Run it with hot reload

Start the entry point through Noir’s development runner:

```sh
dart run noir:run bin/noir_demo.dart
```

You should see the count above a focused button. Press Enter or Space, or click
the button. Each activation changes the count by one.

The recording shows the repository’s larger counter, with a border and extra

If the keyboard does nothing, focus the terminal window. The Button has
`autofocus: true`, so Noir gives it primary focus when the tree mounts. Press
Ctrl+C to exit; Noir restores the terminal modes it owns.

For a normal launch without the source watcher, run
`dart run bin/noir_demo.dart` instead.

## Change the running app

Leave the development runner open. Change `Count:` to `Total:` in the `Text`
widget and save the file. The label changes while the current count and focus
stay in place. If the count was `1`, you should now see `Total: 1`.

The runner watches Dart files under `lib/` and beside the entry point. It asks
the Dart VM to swap the changed sources, then tells Noir to rebuild, lay out,
and paint the retained tree. If an edit does not compile, the last good app
keeps running. Fix the source and save again.

Hot reload does not rerun `main()` or `initState()`, and some structural Dart
changes need a full restart. Runner diagnostics go to
`.dart_tool/noir/run.log`, outside the alternate-screen UI.

`_increment` changes `_count` inside `setState`. Noir keeps the matching `State`
object, calls `build` again, and paints the next frame. The widget declaration
changes; the state that owns the count does not.

Next, use [Widgets and layout](/docs/widgets-layout) to compose a larger screen,
or read [State and lifecycle](/docs/state-lifecycle) before adding controllers,
subscriptions, or animation. The repository’s
[complete Counter](https://github.com/conceptadev/noir/blob/main/example/counter.dart)
adds arrow keys, `+`, `-`, and explicit pointer handling.

To try reusable state hooks, continue with [Hooks](/docs/hooks) and then
[Build a task list](/docs/signals-task-list). Those guides use the unreleased
`noir_signals` companion and currently require a repository checkout.
