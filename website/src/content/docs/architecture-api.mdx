# Architecture and API

Noir keeps each part of the rendering path in one owning layer:

> Widgets declare. Elements preserve identity. RenderObjects layout and record
> paint. The compositor talks to OpenTUI. The native layer owns FFI, memory,
> ABI, and binaries.

Start with `noir.dart`. Add `hooks.dart` when a HookWidget or hook solves a
local lifecycle problem. Use the low-level and FFI libraries only when the
application needs the extra responsibility they expose.

Concrete Element implementations, generated bindings, library discovery, and
recording, display-list, and compositor internals remain framework-owned. A
widget never calls FFI directly; render-object paint goes through
`PaintingContext`, not `Buffer`.
