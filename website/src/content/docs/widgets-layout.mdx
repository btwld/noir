# Widgets and layout

Noir follows Flutter’s declarative layout model, but every size and gap is a
whole terminal cell. Start by describing relationships between widgets. Add an
explicit size only where the interface has a real boundary.

## Compose a status region

`StatusRegion` is a small `StatelessWidget`: a natural-width Badge, a message
that owns the remaining row, a trailing percentage, and a fixed-width progress
bar.

```dart
class StatusRegion extends StatelessWidget {
  const StatusRegion({required this.progress, super.key});

  final double progress;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      spacing: 1,
      children: [
        Row(
          spacing: 1,
          children: [
            const Badge(label: 'BUILD', variant: BadgeVariant.info),
            const Expanded(
              child: Text(
                'Compiling package graph',
                maxLines: 1,
                softWrap: false,
                overflow: TextOverflow.ellipsis,
              ),
            ),
            Text('${(progress * 100).round()}%'),
          ],
        ),
        ProgressBar(value: progress, width: 32),
      ],
    );
  }
}
```

`spacing: 1` inserts one cell only between adjacent children. `Expanded` takes
the row left after the Badge, gap cells, and percentage. The ProgressBar is
deliberately 32 cells wide, so its extent stays predictable as the viewport
changes.

## Think in terminal cells

Widths, heights, padding, offsets, and flex spacing are integers. A row is
usually about twice as tall as a column is wide, so one blank row already
creates substantial vertical separation. CJK characters and many emoji occupy
two columns even though they are one grapheme.

Use the grid as the design constraint:

- Use `spacing: 1` for a normal gap. Two rows is already generous at 80×24.
- Keep controls one row tall unless the control is a viewport or editor.
- Let unused width trail at the end of a region. Do not stretch every child to
  make an 80-column screen look full.
- Clamp one-line table and status text with `maxLines: 1`, `softWrap: false`,
  and an explicit overflow behavior.

## Follow the layout protocol

<ol className="concept-flow layout-protocol">
  <li>
    <strong>Constraints go down.</strong>
    <span>
      A parent tells each child the smallest and largest size it may use.
    </span>
  </li>
  <li>
    <strong>Sizes come up.</strong>
    <span>
      The child chooses an integer-cell size inside those constraints.
    </span>
  </li>
  <li>
    <strong>Parents set positions.</strong>
    <span>
      The parent places each child and establishes its hit-test geometry.
    </span>
  </li>
</ol>

`Flexible` lets a child use less than its flex share. `Expanded` requires it to
fill that share. `SizedBox` sets an exact extent; `ConstrainedBox` adds a
minimum or maximum without promising an exact result.

| When the relationship is…             | Start with               |
| ------------------------------------- | ------------------------ |
| A horizontal or vertical sequence     | `Row` or `Column`        |
| One child owns leftover space         | `Expanded` or `Flexible` |
| Children continue onto another run    | `Wrap`                   |
| Children overlap at cell offsets      | `Stack` and `Positioned` |
| One child is larger than its viewport | `ScrollBox`              |
| Custom content appears above the root | `OverlayPortal`          |
| A centered flow blocks the background | `Modal`                  |
| A command list follows its launcher   | `MenuAnchor`             |
| A child must read the space it gets   | `LayoutBuilder`          |

The [Widget catalog](/docs/widget-catalog) covers the rest of the public
composition surface.

## Read the offered space with LayoutBuilder

`LayoutBuilder` requires the unreleased Noir alpha.5. Use a
[local checkout](/api#evaluate-repository-source) to try this section.

Every other widget declares a size and lets layout resolve it. `LayoutBuilder`
is the one place an application reads the `BoxConstraints` its parent offers,
so a region can show more rows in a tall pane and fewer in a short one.

```dart
LayoutBuilder(
  builder: (context, constraints) => ListView(
    itemCount: items.length,
    height: constraints.maxHeight ?? 8,
    itemBuilder: buildRow,
  ),
)
```

The builder runs during layout and its result is laid out in the same frame,
so the constraints it reads are the constraints its child receives. It runs on
the first layout, on a constraint change, on a widget update, on an inherited
dependency change, and on reassembly; laying the same subtree out again at
unchanged constraints does not run it.

An unbounded axis reports a `null` maximum, so supply a fallback as the example
does. Put `LayoutBuilder` inside a region whose size is already bounded — a
`Panel`, an `Expanded`, or a `SizedBox` — rather than at the root of an
unbounded column.

## Put modal behavior around a Panel

`Modal` owns centered root-overlay placement, a closed Tab loop, focus
restoration, Escape dismissal, and the background pointer barrier. It does not
own colors, borders, or a title. Keep those responsibilities visible by
composing a shrink-wrapped Panel:

```dart
Modal(
  controller: modalController,
  modalBuilder: (context) => Panel(
    title: 'Confirm deployment',
    child: Column(
      mainAxisSize: MainAxisSize.min,
      children: [
        const Text('Deploy the reviewed revision?'),
        Button(label: 'Cancel', onPressed: modalController.close),
      ],
    ),
  ),
  child: Button(label: 'Review', onPressed: modalController.open),
)
```

Omitting a fixed Panel height lets the modal fit its content and remain
centered as the terminal resizes.

## Put borders around regions, not every widget

A border occupies the outside cells of its box. `Panel` provides the normal
themed region with an optional title and focused state, so a second Text heading
inside the same box creates duplicate chrome.

```dart
Panel(
  title: 'Build log',
  width: 24,
  child: log,
)
```

Omit `width` and `height` when the region should shrink-wrap its child. When a
viewport or label needs a fixed extent, remember that a Panel's dimensions
include its border and horizontal inset. Its colors come from Theme; pass
`color` or `borderColor` only for a deliberate override. Reach for Container
and BoxDecoration when the region needs custom geometry instead of Panel's
standard shape.

## Leave paint and FFI below widgets

Widgets declare configuration. Paint recordings and FFI stay in the layers
described in [Architecture](/docs/architecture-api). The repository’s
[Layout Basics](https://github.com/conceptadev/noir/blob/main/example/layout_basics.dart)
is a runnable comparison of main-axis alignment and flex distribution.
