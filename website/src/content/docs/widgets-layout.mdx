# Widgets and layout

Widgets describe immutable configuration. Elements preserve identity, while
RenderObjects turn constraints into integer-cell geometry and record paint for
the compositor. Widgets never call FFI or draw directly into an OpenTUI buffer.

## Compose in cells

`Row`, `Column`, `Container`, `Padding`, `SizedBox`, `Align`, `Flexible`, and
`Expanded` all use whole terminal cells. A `spacing` value is the number of
cells between children. Borders occupy cells too, so content in a bordered
region begins on the first inner row and column.

```dart
Row(
  spacing: 1,
  children: [
    const Text('Status'),
    Expanded(child: ProgressBar(value: 0.5, width: 24)),
  ],
)
```

Start content at the top and leading edge. If a shrink-wrapped panel has unused
rows, reduce its height instead of vertically centering the copy. The
[layout basics example](https://github.com/leoafarias/noir/blob/main/example/layout_basics.dart)
shows the smallest runnable composition.

## Resolve constraints before paint

Render objects receive constraints, choose a size, lay out their children, and
record paint through `PaintingContext`. The compositor carries those display
lists to OpenTUI buffers. Keeping that boundary intact makes layout, clipping,
hit testing, and native ownership testable.

Use `Stack` and `Positioned` for integer-cell overlays, `Wrap` for bounded runs,
and `ScrollBox` for one overflowing child. Paint that intentionally leaves local
bounds must use `PaintingContext` and `TuiCanvas.clipRect`.

## Design for the terminal grid

Each box-drawing cell already has optical space around its glyph. Extra padding
borrowed from browser interfaces and vertically centered card copy usually
waste scarce rows. Put a region name in `Border.title`; adding another `Text`
heading inside creates a second header.

For larger compositions, inspect
[Components](https://github.com/leoafarias/noir/blob/main/example/components_demo.dart)
and the [Widgets Tour](https://github.com/leoafarias/noir/blob/main/example/widgets_tour.dart).
