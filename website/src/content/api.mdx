# API

Most applications need only `package:noir/noir.dart`. Import a lower-level
surface only when your code owns the corresponding framework or native
responsibility.

## Use the commands shipped with Noir

| Command                                      | Purpose                                                        | What it does not prove                                       |
| -------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------ |
| `dart run noir:run <entrypoint> [arguments]` | Run an app with source watching and hot reload                 | Real-terminal behavior still depends on the current terminal |
| `dart run noir:health_check`                 | Verify native-asset resolution and a headless render lifecycle | It does not enter raw mode or validate terminal protocols    |

The development runner and its restart boundaries are in
[Getting started](/docs/getting-started). Noir Driver is repository-only and is
not a public widget-test harness; see [Testing](/docs/testing).

## Read the published symbols

Use the [generated API reference on pub.dev](https://pub.dev/documentation/noir/latest/)
for published symbols and signatures. The repository can be ahead of the latest
prerelease, so match the reference to the version in your `pubspec.lock`.

## Evaluate repository source

To try an unreleased API, use a local checkout of the private Noir repository.
The paths below assume it sits beside your application directory:

```yaml
dependencies:
  noir:
    path: ../noir
```

For hooks or Signals, also point to the companion in that same checkout:

```yaml
dependencies:
  noir: ^0.0.1-alpha.5
  noir_signals:
    path: ../noir/packages/noir_signals
dependency_overrides:
  noir:
    path: ../noir
```

Run `dart pub get` from your application directory. Both packages come from
one revision; `noir_signals` requires Noir alpha.5, which is not yet published.
The override also routes the companion’s Noir dependency to your checkout.

Do not copy generated bindings, bundled native artifacts, or framework-owned
internals into an application to reach a newer feature. Either stay on the
published surface or pin and evaluate one repository revision as a unit.

For the ownership boundaries behind these surfaces, read
[Architecture](/docs/architecture-api). Check
[Platform support and limitations](/docs/platform-limitations) before choosing
a deployment target.
